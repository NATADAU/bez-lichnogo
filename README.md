# Без личного — подготовка для GitHub Pages

Интерфейс сохранён. PDF.js **6.5.438** подключается локально из `vendor/` (ES-модули `.mjs`).

## Для публикации

1. Создать отдельный репозиторий GitHub и загрузить файлы проекта, включая `.github/workflows/pages.yml`.
2. В настройках репозитория **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Проверить вкладку **Actions**: сборка должна завершиться успешно; появится ссылка на сайт.
4. Перед работой с персональными данными провести проверку на опубликованном адресе (см. ниже).

GitHub Actions при сборке загружает PDF.js `6.5.438` и кладёт его рядом с приложением. Посетители получают библиотеку **с того же GitHub Pages**, не с CDN.

**Локальная подготовка** (только внутри папки проекта):

```bash
npm install --no-save --ignore-scripts --no-audit --no-fund pdfjs-dist@6.5.438
mkdir vendor
copy node_modules\pdfjs-dist\build\pdf.min.mjs vendor\pdf.min.mjs
copy node_modules\pdfjs-dist\build\pdf.worker.min.mjs vendor\pdf.worker.min.mjs
```

Затем открыть через локальный веб-сервер (не через `file://` — модули и worker так не работают):

```bash
npx --yes serve -l 4173 .
```

## Важно о безопасности

- **Frost не подходит для надёжного обезличивания**: размытие может сохранять признаки исходных данных.
- Для секретных сведений используйте только **непрозрачные цветные плашки** и проверяйте весь документ.
- Используется PDF.js **6.5.438** (актуальная стабильная на момент подготовки). В PDF.js 5+/6 опция `isEvalSupported` удалена: выполнение в движке отключён. XFA отключён (`enableXfa: false`).
- В `index.html` задана **Content-Security-Policy**: скрипты и worker только с своего сайта, сетевые подключения страницы запрещены (`connect-src 'none'`). Это усиливает защиту, но не заменяет осторожность с файлами.
- **Не загружайте реальные персональные данные**, пока сайт и экспорт не проверены на целевой платформе.
- На GitHub должен размещаться только код приложения, **без исходных PDF с ПДн**.

## Проверки перед использованием

- В Chrome/Edge: `F12` → **Network** → загрузить тестовый PDF и сохранить; убедиться, что нет запросов к внешним доменам.
- Убедиться, что `vendor/pdf.min.mjs` и `vendor/pdf.worker.min.mjs` загружены с того же сайта.
- Проверить 1 и несколько страниц, копирование областей, экспорт, открытие скачанного PDF.
- Для проверки удаления данных использовать вымышленную таблицу и непрозрачные плашки; смотреть края областей.

Локальные автопроверки (вымышленные данные): `node scripts/check-region-math.mjs`, затем сайт с `?testapi=1` и скрипт `scripts/bootstrap-smoke.js` (не входит в публикацию Pages).
