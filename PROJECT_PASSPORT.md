# Паспорт проекта «Без личного»

Документ для передачи контекста между сеансами разработки и ИИ-агентами.  
Описывает **уже существующее** приложение по состоянию кода и репозитория.  
Непроверенные утверждения помечены отдельно.

---

## 1. Назначение и история

**Для кого:** сотрудники образовательной организации, которым нужно скрывать персональные данные в сканированных PDF и которые не владеют графическими редакторами.

**Зачем:** раньше документ приходилось конвертировать в изображения, обрабатывать в Figma (или аналоге), экспортировать и снова собирать в PDF. Приложение делает загрузку, выделение областей, размытие/плашки и сохранение PDF в одном простом браузерном интерфейсе.

**Принцип:** обработка на устройстве пользователя в браузере; без установки графических редакторов.

---

## 2. Основные функции (реализовано в коде)

Подтверждено файлами `index.html` и `app.js`:

| Возможность | Примечание |
|-------------|------------|
| Загрузка PDF | Через `<input type="file">`, разбор через PDF.js |
| Загрузка изображений | PNG, JPEG, WebP |
| Многостраничные PDF | Листание страниц, отдельный набор областей на страницу |
| Лимит страниц | Не больше **10** страниц в одном PDF |
| Лимит размера | Не больше **25 МБ** |
| Подсказка у кнопки загрузки | «Один PDF-файл — до 10 страниц, размером не более 25 МБ» |
| Несколько независимых областей | Рисование мышью, добавление/удаление |
| Frost Blur | Размытие через canvas `filter: blur(...)` исходной страницы |
| Непрозрачные цветные плашки | Заливка цветом в области |
| Пипетка | Усреднение цвета с исходного canvas |
| Восемь маркеров | Изменение размера; перемещение области |
| Стрелки клавиатуры | Точная подстройка выбранной области |
| Копирование областей на все страницы | С подтверждением |
| Показать оригинал | Временно без наложений (только просмотр) |
| Скачивание PDF | Новый PDF из растровых JPEG-страниц (свой сборщик, без pdf-lib) |
| Демо-документ | Кнопка «Пример» с вымышленными данными |

**Не менять без запроса:** расположение инструментов, механика Frost / пипетки / маркеров, логика экспорта (уже согласовано с заказчиком и доработано по безопасности/теме).

## 3. Техническая архитектура

### Стек (актуально)

| Компонент | Роль |
|-----------|------|
| `index.html` | Разметка, CSS (тема ЦЛП), CSP |
| `app.js` | Вся логика UI и PDF (ES-модуль) |
| **PDF.js `6.5.438`** (`pdfjs-dist`) | Открытие и отрисовка PDF на canvas |
| Локальный `vendor/` | `pdf.min.mjs` + `pdf.worker.min.mjs` (в git **не** хранится; появляется при сборке или `prepare-vendor`) |
| GitHub Actions | Сборка сайта + установка PDF.js + деплой Pages |
| GitHub Pages | Публикация статического сайта |

### Поток данных

1. Пользователь выбирает файл → чтение в браузере (`arrayBuffer` / Image).
2. PDF.js рендерит страницу на canvas (параметр `canvas`, worker с того же origin).
3. Области хранятся в памяти (`regionsByPage`), координаты относительные 0…1.
4. Экспорт: каждая страница снова рендерится → накладываются области → JPEG → новый PDF 1.4 **без** исходных текстовых слоёв/объектов исходного PDF.

### Сборка и публикация

- Workflow: `.github/workflows/pages.yml`
- На push в `main` (и `workflow_dispatch`): `npm install … pdfjs-dist@6.5.438`, копирование в `site/`, проверка отсутствия внешних `http(s)://` в `index.html`/`app.js`, деплой Pages.
- В репозитории **нет** `node_modules/` и `vendor/` (см. `.gitignore`).

### Тестовые вспомогательные средства (не часть UI продукта)

- `scripts/check-region-math.mjs` — проверка математики границ плашек (Node).
- `scripts/prepare-vendor.ps1` — локальная подготовка `vendor/`.
- `scripts/bootstrap-smoke.js` + `page-world-smoke.js` — автопроверка в браузере при `?testapi=1` (тестовый API `window.__BEZ__`).
- `fixtures/sample-2pages.pdf` — вымышленные данные для тестов.

## 4. Безопасность

### Подтверждённые меры и свойства кода

- Обработка файлов **в браузере**; в коде приложения нет отправки содержимого документов на сервер приложения.
- PDF.js отдаётся **с того же origin**, что и сайт (сборка кладёт файлы в `site/vendor/`).
- **CSP** в `index.html`: в т.ч. `script-src 'self'`, `worker-src 'self'`, `connect-src 'none'`.
- При открытии PDF: `enableXfa: false`; в PDF.js 5+/6 eval в движке отключён (опция `isEvalSupported` снята).
- При экспорте **цветная плашка** заменяет пиксели внутри прямоугольника (с запасом края 1 px и floor/ceil координат).
- Экспорт — **новый** растровый PDF, не копия структуры исходного файла.
- UI и сохранение предупреждают: **Frost не является безопасным обезличиванием**.
- Пользователю явно сказано проверять все страницы и края перед передачей файла.

### Ограничения (важно для агентов и пользователей)

- Frost Blur **может оставлять** признаки исходных данных; для передачи третьим лицам — только непрозрачные плашки + ручная проверка.
- CSP и локальная обработка **снижают** риски, но **не гарантируют** абсолютную безопасность (в т.ч. сложные/вредоносные PDF, ошибки пользователя, уязвимости браузера/библиотек).
- Лимиты 10 страниц / 25 МБ — продуктовые ограничения этой версии, не криптографическая защита.

## 7. Правила дальнейшей разработки

1. Не переписывать приложение с нуля.
2. Не менять согласованный интерфейс и работающие инструменты без явного запроса.
3. Новые функции — в **отдельных ветках**, merge в `main` только после проверки.
4. Не отправлять персональные данные в репозиторий и во внешние сервисы.
5. Для тестов — только вымышленные данные.
6. После изменений, затрагивающих PDF, — проверять открытие / области / экспорт.
7. Не публиковать и не пушить без отдельного разрешения владельца.
8. Не устанавливать глобальные пакеты и не менять настройки компьютера без разрешения.
9. После существенных изменений **обновлять этот паспорт**.
10. В ответах и документах разделять: **проверенные факты**, **ограничения**, **планы**.
